Privacy Policy

Effective Date: November 2026 · App: CleanDoc — Stale-Page & Offboarding Cleaner for Confluence

1. Zero-Egress "Runs on Atlassian" Architecture

CleanDoc runs 100% natively on Atlassian Forge (nodejs22.x) using Atlassian Forge SQL. The application declares zero external.fetch permissions in manifest.yml. Your Confluence and Jira data never leaves Atlassian Cloud infrastructure, and no external servers or third-party analytics services are used.

2. Data Processed Inside Forge SQL

CategoryFields StoredPurpose
Page MetadataPage ID, space key/ID, title, URL, last modified timestamp, orphan flag, Rovo Pollution Score, clean statusIdentify stale pages and track cleanup status
OwnershipOwner Atlassian Account ID, display name, account status, reassigned owner IDDetect offboarded employees and support bulk reassignment
Jira KeysLinked Jira issue keys (e.g. PROJ-42), resolved Jira keysIdentify documentation linked to closed Jira work
Audit TrailAction type, actor Account ID/name, affected page IDs, timestampProvide exportable CSV governance logs

No Page Body Storage: CleanDoc never stores Confluence page body content. Page storage XML is parsed transiently in memory during scans only to extract Jira issue keys.

3. Data Retention & Deletion

All data resides inside your tenant-isolated Forge SQL database and respects Atlassian Cloud Data Residency. Uninstalling CleanDoc triggers automatic platform deprovisioning by Atlassian Forge.

4. Subprocessors & Contact

CleanDoc uses zero external subprocessors beyond Atlassian Cloud / Forge itself. Publisher: Pierre Cassagnettes — CleanDoc (France / European Union). For GDPR, data deletion, or privacy inquiries, contact pierrecassagnettes+cleandoc@gmail.com.
